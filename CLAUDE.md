# Fretboard Practice — Claude Code guide

Guitar practice app (React 19 + Vite, zero runtime deps beyond react/react-dom). 12-week key rotation
through the cycle of fourths, major + harmonic-minor tracks, guided sessions, drills, theory tools,
and a global metronome. Pure static SPA — no backend, all state in localStorage.

## Commands

- `npm run dev` — Vite dev server
- `npm test` — vitest data-integrity suite (src/data/data.test.js); run after touching src/data or src/theory
- `npm run build` — production build to dist/ (deployed on Render via render.yaml, hash routing → no rewrite rules)

## Architecture

- `src/data/` — constants. **schedule.js, scheduleHarmMinor.js, cagedShapes.js are verbatim extractions**
  from the legacy `fretboard-practice.jsx` (root), generated by `node scripts/extract-data.mjs`.
  Never hand-edit or reformat these three; re-run the script instead. The test suite pins the CAGED
  dot count (1762) to catch accidental data loss.
- `src/theory/` — pure derivation functions (diatonic chords, modal tables, voicing solver, note maps).
- `src/audio/` — `engine.js` owns the single AudioContext (buses: click/chord/drone → master → compressor).
  `metronome.js` is a lookahead scheduler singleton. `voices.js` synthesizes plucks/drone.
- `src/components/Fretboard/` — one Fretboard renders everything (full neck, CAGED cards, drill reveals).
- `src/state/` — `storage.js` (fp.* localStorage keys, schema version, backup import/export staging),
  `AppState.jsx` (context; merges DEFAULTS over stored settings so new keys get defaults for existing users).
- `src/pages/` — routed views (hash routing via useHashRoute; no router lib).
- `src/LegacyApp.jsx` + root `fretboard-practice.jsx` — legacy reference, scheduled for deletion once
  final parity/polish pass is done. Don't import from them.

## Invariants that are easy to get wrong

- **String numbering**: markers and CAGED dots use `string`/`s` ∈ 1..6 where **1 = high E, 6 = low E**.
  `OPEN_STRINGS` (data/notes.js) is indexed 0 = string 6 (low E) — convert with `OPEN_STRINGS[6 - s]`.
  `OPEN_MIDI` in audio/voicing.js maps string number → midi directly.
- **CAGED templates are movable shapes** drawn at arbitrary card positions (e.g. the "C shape" template's
  root is drawn on pitch D). Anchor any key-mapping by the template's own root dot pitch class
  (see `buildCagedBands`/`cagedShapePositions` in theory/noteMap.js) — never assume shape letter = root pc.
- **Metronome timing**: there is ONE engine singleton shared by the global panel, loop players and sessions.
  Mid-playback meter/subdivision changes must go through `metronome.update()` (applied at the next beat
  boundary — instant re-anchoring shifts the pulse; this was a real bug). Subdivisions support non-uniform
  per-beat patterns (e.g. dotted 8th+16th = `[0, 0.75]`).
- **Metronome config** is one persisted object (`fp.metronome`) exposed via `useMetronomeConfig()` from
  components/metronome/metroShared.js — never create separate bpm/sig state. Click volume goes through
  `applyClickVolume()` (slider drives bus to 1.6×). Each click sound uses ONE timbre; accents differ only
  by gain/brightness (user explicitly rejected mixed timbres).
- **Audio needs a user gesture** — every play path runs through engine `ensureRunning()`; unlock is attached
  at app root. Never call AudioContext APIs at module top level.
- **Persistence**: new settings go into `DEFAULTS` in storage.js (AppState merge covers existing users).
  Breaking shape changes: bump SCHEMA_VERSION + handle in `migrate()`. Backup export/import iterates
  `Object.values(KEYS)` — new keys are picked up automatically; `sessionDraft` stays device-local.
- **Readability** (explicit user feedback, twice): dark theme must stay bright — UI text ≥ ~12.5px
  (body 14px), no grays darker than `--text-faint` for readable content, faded fretboard states
  ≥ 0.26 dot / ≥ 0.68 text opacity. Use the token tiers in theme/tokens.css, not hard-coded grays.
- **Fretboard look**: 24 frets; three board finishes (dark/wood/white) in components/Fretboard/layout.js
  THEMES — marker chrome (outlined-dot fill, faded text) is per-theme; keep all three readable when
  touching marker rendering.
